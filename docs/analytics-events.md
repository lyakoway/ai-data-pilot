# События аналитики

События уходят одновременно в **Google Analytics 4** (`gtag('event', …)`) и **Яндекс.Метрику** (`ym(…, 'reachGoal', …)`).

Исходники:

- имена: `frontend/src/lib/analytics/constants.ts`
- отправка: `frontend/src/lib/analytics/trackAnalytics.ts`
- разметка счётчиков: `frontend/src/lib/analytics/injectAnalyticsMarkup.ts`

Переменные окружения (Vite, вшиваются на сборке):

- `VITE_GA_MEASUREMENT_ID`
- `VITE_YANDEX_METRIKA_ID`

ID лежат в закоммиченном `frontend/.env` — они публичные (видны в HTML/JS клиента).
Прод (HF Spaces / Docker): Vite вшивает их при `npm run build` внутри Docker-сборки.
Variables в Settings HF на этапе Docker-build обычно **недоступны**, поэтому без
`frontend/.env` счётчики на демо не появятся. Пустое значение = счётчик не
подключается (инжект-код превращается в no-op).

В Яндекс.Метрике для отчётов по целям создайте JavaScript-цели с теми же
идентификаторами, что в колонке «Идентификатор» ниже.

Тип цели: **Целевое событие** (ex JS-событие). Условие: **совпадает**.
Pageview целью не оформляется — это обычные просмотры (первый заход шлёт
`ym init` / `gtag config`).

## Цели для Яндекс.Метрики (все события)

| Идентификатор | Название цели (пример) | Зачем |
|---------------|------------------------|--------|
| `question_sent` | Отправка вопроса | Пользователь задал вопрос Атласу или Доку |
| `answer_received` | Ответ получен | Стрим завершился без ошибки |
| `question_error` | Ошибка вопроса | Сбой стрима или статус `error` |
| `new_chat` | Новый чат | Кнопка «+ New chat» очистила диалог |
| `agent_pin` | Выбор агента | Прикрепили Атласа или Дока |
| `agent_mode_change` | Авто-роутинг | Переключили тумблер авто-выбора агента |
| `model_change` | Смена модели | Выбрали другую LLM в селекторе |
| `datasource_change` | Смена источника | Выбрали другой источник данных |
| `db_modal_open` | Модалка БД | Открыли подключение PostgreSQL / ClickHouse |
| `file_upload` | Загрузка CSV/Excel | Файл загружен как SQL-источник |
| `file_upload_error` | Ошибка загрузки файла | Сбой upload CSV/Excel |
| `scenario_created` | Сценарий сохранён | «Сохранить как сценарий» |
| `scenario_run` | Сценарий запущен | Запуск сохранённого сценария |
| `answer_feedback` | Оценка ответа | 👍/👎 под ответом |
| `source_click` | Открытие источника | Клик по файлу источника → просмотрщик |
| `citation_click` | Клик по цитате `[n]` | Маркер в тексте ответа |
| `excel_download` | Скачивание Excel | Экспорт результата в Excel |
| `document_upload` | Загрузка документа | Документ в базу знаний Дока |
| `document_upload_error` | Ошибка загрузки документа | Сбой upload в панели документов |
| `document_delete` | Удаление документа | Удалили документ из базы знаний |
| `provider_error_modal` | Модалка «Модель недоступна» | Сбой распознан как провайдерский |
| `provider_error_contact` | «Связаться с нами» | Клик по контакту в модалке провайдера |
| `theme_toggle` | Смена темы | Светлая / тёмная |
| `language_toggle` | Смена языка | RU ↔ EN |

**Приоритет (если не все сразу):** `question_sent` → `answer_received` →
`answer_feedback` → `file_upload` → `scenario_run`.

## Вопросы и ответы

| Событие | Когда | Параметры |
|---------|--------|-----------|
| `question_sent` | Отправка вопроса (composer, чип-подсказка, Excel-флоу) | `agent` (`auto` \| `atlas` \| `doc`), `model`, `excel` (`true` на forceExcel) |
| `answer_received` | Стрим завершился, статус не `error` | `agent` (`atlas` \| `doc`), `status` (`ok` \| `demo` \| `partial`), `took_ms`, `steps` (число tool-шагов трассировки) |
| `question_error` | `onError` стрима или результат со статусом `error` | `agent`, `model`, `message` (до 120 символов) |
| `new_chat` | Кнопка «+ New chat» | — |

`answer_received` — аналог `agent_run_done` из ai-RAG-chat: фиксирует и успех,
и время ответа (`took_ms`) — по нему видно деградацию модели/холодный старт.

## Агенты и авто-роутинг

| Событие | Когда | Параметры |
|---------|--------|-----------|
| `agent_pin` | Клик по карточке агента в сайдбаре | `agent` (`atlas` \| `doc`) |
| `agent_mode_change` | Тумблер «Auto-select agent» | `auto` (`true` \| `false`) |

Клик по агенту всегда переводит режим в ручной — `agent_mode_change` c
`auto: false` при этом не дублируется.

---

## Источники данных и модель

| Событие | Когда | Параметры |
|---------|--------|-----------|
| `datasource_change` | Смена источника в dropdown (topbar / settings drawer — общий контрол) | `datasource_id` |
| `model_change` | Смена LLM в dropdown | `model` (id модели, напр. `glm-4.6`) |
| `db_modal_open` | Кнопка PostgreSQL / ClickHouse | `db` (`postgres` \| `clickhouse`) |
| `file_upload` | CSV/Excel успешно загружен как SQL-источник | `filename` |
| `file_upload_error` | Ошибка загрузки CSV/Excel | `filename`, `message` (до 120 символов) |

Автоподстановка источника/модели кодом (не пользователем) события не шлёт.

## Сценарии

| Событие | Когда | Параметры |
|---------|--------|-----------|
| `scenario_run` | Фактический запуск сохранённого сценария | `scenario_id`, `agent` |
| `scenario_created` | «Сохранить как сценарий» успешно создал сценарий | `agent` |

Открытие модалки с параметрами сценария само по себе не событие — считается
только запуск.

## Оценка и источники ответа

| Событие | Когда | Параметры |
|---------|--------|-----------|
| `answer_feedback` | 👍/👎 под ответом | `value` (`up` \| `down`), `agent` |
| `source_click` | Клик по файлу источника → просмотрщик | `filename`, `page?` |
| `citation_click` | Клик по маркеру `[n]` в тексте ответа | `index` |
| `excel_download` | «Скачать Excel» в карточке результата | — |

После `source_click` сразу открывается просмотрщик. Повторный клик по той же
оценке услуги не снимает (в отличие от ai-RAG-chat) — голос отправляется один
раз на карточку.

## База знаний Дока

| Событие | Когда | Параметры |
|---------|--------|-----------|
| `document_upload` | Пакет документов загружен в панель «Документы» | `count` |
| `document_upload_error` | Ошибка upload в панели документов | `message` (до 120 символов) |
| `document_delete` | Удаление документа из базы знаний | `id` |

---

## Ошибки провайдера

| Событие | Когда | Параметры |
|---------|--------|-----------|
| `provider_error_modal` | Модалка «Модель недоступна» показана (баланс/ключ провайдера) | `message` (до 120 символов) |
| `provider_error_contact` | Клик «Связаться с нами» в модалке | — |

Показ модалки дополняет парный `question_error` (тот же сбой): `question_error`
фиксирует сбой, `provider_error_modal` — что он распознан как провайдерский
и посетителю показано объяснение с контактом.
