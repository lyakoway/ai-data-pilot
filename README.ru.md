# 📊 AI Data Pilot — мультиагентная аналитика

> **Live demo:** [lyakoway-ai-data-pilot.hf.space](https://lyakoway-ai-data-pilot.hf.space/)

Аналитика на естественном языке: SQL, график и объяснение. Два узких агента —
**Олег** (Text-to-SQL, графики, Excel) и **Ксюша** (RAG по документам и
загрузкам) — плюс двухуровневый авто-роутер. В английском UI: Data Agent /
Knowledge Agent.

Этот репозиторий — самостоятельное **личное демо** на тестовом наборе
(RideGo ~21 тыс. поездок). Тот же класс задачи, что у production мультиагентной
аналитики — **не** исходный код и не продовые базы той системы. Цифры SQL ниже
совпадают со страницей кейса
[lyakoway.vercel.app/portfolio/ai-data-pilot](https://lyakoway.vercel.app/portfolio/ai-data-pilot).
Продовые базы — под NDA.

<sub>Демо на бесплатном тарифе может «засыпать» — первый заход после простоя
~1 мин. Векторная модель (fastembed) грузится при первом поиске Ксюши (~10 с).</sub>

**Что ушло в прод — три решения по замерам:**

1. **Считает Python** — тренды, проценты, топ-N и z-score в Python-слое. LLM
   пишет текст, не считает бизнес-цифры.
2. **Упавший SQL — контракт** — SQL Guard (SELECT-only) + две переписки +
   честная ошибка. Тихой подмены результата нет.
3. **Два агента, не один промпт** — Олег для SQL, Ксюша для документов,
   двухуровневый роутер; решение видно в SSE-trace.

Headline SQL-качества на публичном тестовом паке (GLM-4.6): **~85%
нормализованной точности результата** (те же числа без алиасов, порядка строк
и формата чисел — не string exact-match). **~98% execution** значит только,
что запрос выполнился. **2ч → 2мин** на отчётность — прод МТС, не это демо.

## Ключевые возможности

- 🧭 **Двойной авто-роутинг** — по агенту (данные → Олег, документы → Ксюша) и
  по источнику. LLM-классификация + детерминированная эвристика как fallback.
- 👤 **Олег (Data Agent)** — ReAct tool-calling, SSE-trace, self-correction
  (до 2 раундов), детерминированная аналитика на Python.
- 👩‍💻 **Ксюша (Knowledge Agent)** — гибрид BM25 + вектора (fastembed).
  Ablation поиска — в кейсе RAG Chat, не здесь. Цитаты `[1]`, просмотрщик.
- 🗄️ PostgreSQL, ClickHouse, CSV/Excel, виртуальный источник «Все загрузки»
  (JOIN между файлами).
- 🤖 **13 конфигураций.** **GLM-4.6 — default** (на ней снята оценка ~85%).

## Evaluation

Цифры совпадают со
[страницей кейса](https://lyakoway.vercel.app/portfolio/ai-data-pilot).
SQL-оценка — публичный пак RideGo, не продовые базы МТС.

**174 pytest-теста** на изолированных temp-SQLite, без ключей.

**Качество SQL — held-out, живой прогон GLM-4.6:**

| Метрика | Результат |
|---|---|
| **Нормализованная точность результата** (те же числа после канонизации) | **~85%** |
| SQL Execution Accuracy (запрос выполнился — это не правильность) | ~98% |

### Латентность по моделям

| Модель | План (LLM) | Выполнение (БД) | Ответ (LLM) | Итого | SQL ok |
|---|---|---|---|---|---|
| **GLM-4.6 (Z.ai) — по умолчанию** | 13.5 с | 12 мс | 16.3 с | ~29.8 с | 2/3 |
| GLM-5.2 (Z.ai) | 7.0 с | 6 мс | 9.4 с | ~16.4 с | 3/3 |
| GLM-5.3-flash (Z.ai) | 7.0 с | 8 мс | 4.8 с | ~11.9 с | 2/3 |
| GLM-5.3 (Z.ai) | 13.8 с | 11 мс | 5.1 с | ~19.0 с | 1/3 |

<sub>Медианы 3 прогонов **одного** вопроса. GLM-4.6 остаётся default: ~85%
сняты на ней. GLM-5.2 быстрее на этом семпле; GLM-5.3-flash ещё быстрее, но
SQL слабее. Полный цикл **~16–30 с** — не дашборд за долю секунды.</sub>

## Известные ограничения

- Нет санитизации prompt injection в загруженных файлах Ксюши.
- Routing/retrieval golden set маленькие; pytest retrieval (n=8) даёт 1.0 на
  всех режимах и не дискриминирует поиск.
- Self-correction покрыта юнит-тестами, не измерена как headline-метрика.
- Single-turn, без памяти диалога.
