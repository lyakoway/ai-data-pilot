# PostgreSQL DataSource — план

## Контекст

Добавляем Олегу возможность строить SQL и отвечать по **реальной внешней PostgreSQL** базе. Это естественное расширение DataSource-абстракции из Фазы 2: новый `kind: "postgres"` рядом с `ridego` и `csv`.

**Решения пользователя:**
- Тестирование: **docker-compose** (поднимем локальный Postgres, засеем тестовыми данными)
- Подключение: **env var + UI форма** (преднастроенный через env + интерактивное добавление через UI)

## Архитектура

### DataSource расширение
Новый kind `"postgres"` в `datasources.py`:
- Метаданные: `host`, `port`, `database`, `username`, `password` → хранятся в новой колонке `connection TEXT` (JSON) в datasources таблице
- `get_engine_for` → `create_engine("postgresql+psycopg2://user:pass@host:port/db")`
- `get_schema_catalog` → **автоинтроспекция** через `information_schema.columns` (кэшируется при регистрации)

### Schema introspection
При регистрации источника выполняем:
```sql
SELECT table_name, column_name, data_type
FROM information_schema.columns
WHERE table_schema = 'public'
ORDER BY table_name, ordinal_position
```
Строим catalog-текст (как SCHEMA_CATALOG, но авто-сгенерированный). Кэшируем в metadata. Кнопка "обновить схему" — переинтроспекция.

### Dialect-aware промпт
`PLAN_SYSTEM` сейчас хардкодит «SQLite синтаксис». Добавляю `_dialect_note(kind)`:
- sqlite/csv → «SQLite синтаксис (date(), julianday)»
- postgres → «PostgreSQL синтаксис (DATE_TRUNC, EXTRACT, ::cast)»

sql_guard wrapping (`SELECT * FROM (...) AS _q LIMIT N`) работает в обоих диалектах.

### Тестовая БД (docker-compose)
Поднимаем Postgres 16, засеиваем e-commerce схемой:
- `products` (id, name, category, price, stock)
- `customers` (id, name, city, country, segment)
- `orders` (id, customer_id, product_id, quantity, total, order_date, status)

~500 заказов, 50 продуктов, 100 клиентов. Олег сможет: «топ продуктов по выручке», «продажи по категориям», «сегменты клиентов».

### Безопасность
- Password хранится в `connection` JSON в app.db, **никогда не возвращается на frontend** (маскируется `****`)
- Connection string строится только server-side
- `sql_guard` запрещает мутации (DROP/DELETE/etc.) — работает одинаково для всех диалектов

### Env-преднастройка
`POSTGRES_URL=postgresql://user:pass@host:port/db` → при старте регистрируется источник `postgres-env` автоматически (через lifespan).

## Критерии готовности
1. `POSTGRES_URL` задан → при старте источник появляется в селекторе.
2. UI форма «+ PostgreSQL» → вводишь connection → тест → схема интроспектируется → источник в селекторе.
3. Олег строит **PostgreSQL-синтаксис SQL** (DATE_TRUNC, EXTRACT), не SQLite.
4. «Топ продуктов по выручке» на тестовой БД → таблица + график + инсайты.
5. Password не утекает на frontend (маскировка).
6. Все 111 существующих тестов остаются зелёными.

## Риск-митигация
- **psycopg2-binary** может не собраться на HF Spaces (Alpine) → fallback: при недоступности Postgres драйвера, источник просто не создаётся (graceful). import guarded.
- **Connection failure** → понятная ошибка в UI, не краш.
- **Большая схема** (сотни таблиц) → лимит интроспекции (top-50 таблиц по размеру).
- **sql_guard wrapping** совместим с Postgres (подзапрос + LIMIT работает).
