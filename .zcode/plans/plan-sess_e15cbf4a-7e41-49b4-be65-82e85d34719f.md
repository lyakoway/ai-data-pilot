# Excel (.xlsx) загрузка — план

## Контекст

Сейчас работает только CSV-загрузка (`ingest_csv` в `datasources.py`, route `/api/datasources/upload`). `openpyxl==3.1.5` **уже в requirements** (используется для Excel-экспорта), так что новых зависимостей не нужно.

**Решения пользователя:**
- Формат: только `.xlsx`
- Многолистовые файлы: **каждый лист → отдельный источник данных**

## Архитектурный подход

### Рефакторинг ядра инжестии
Сейчас `ingest_csv(raw_name, rows_text)` делает всё: парсит текст → угадывает типы → создаёт таблицу → регистрирует. **Разделю ответственность:**

1. **Выделю `ingest_rows(raw_name, header, rows)`** — общее ядро, не зависит от формата. Принимает уже распарсенные `(header: list[str], rows: list[list[Any]])`. Здесь живёт типизация, создание таблицы, регистрация. Существующая логика типизации (`_infer_col_kind`) обобщится: сейчас она работает со строками, а от Excel будут приходить уже типизированные значения (`int`/`float`/`datetime`/`str`) — типизация станет точнее.

2. **`ingest_csv(raw_name, rows_text)`** — тонкий адаптер: парсит CSV-текст → `(header, rows)` → вызывает `ingest_rows`. Поведение CSV не меняется.

3. **`ingest_xlsx(raw_name, file_bytes)` → list[dict]** — новый адаптер для Excel. Возвращает **список** метаданных источников (по одному на лист). Использует `openpyxl.load_workbook(io.BytesIO(data), read_only=True, data_only=True)`:
   - `read_only=True` — стриминговое чтение, эффективно по памяти
   - `data_only=True` — значения вместо формул (важно: иначе получим `=SUM(A1:A2)` вместо результата)

### Многолистовый режим
- Прохожу по всем непустым листам `wb.worksheets`
- Для каждого: первая строка = заголовок, остальные = данные
- Каждый лист → `ingest_rows(f"{file_stem} — {sheet.title}", header, rows)` → отдельный источник со своим `id` и `table_name`
- **Именование:** `{ИмяФайла} · {Лист}` (напр. «Продажи Q3 · По Регионам»)
- **Пропуск пустых листов:** лист без данных (только заголовок или пустой) → пропускается, не создаёт источник
- Если **все** листы пустые → ошибка «файл не содержит данных»

### Типизация Excel-значений
`openpyxl` с `data_only=True` возвращает Python-типы:
- Число → `int`/`float` → маппится в `INTEGER`/`REAL`
- Дата/время → `datetime`/`date` → конвертируется в ISO-строку → `TEXT` (как сейчас для CSV-дат)
- Строка/None → `TEXT`/`NULL`

Обобщение `_infer_col_kind`: если значения уже типизированы (`isinstance(v, int)`), используем это напрямую, не угадываем по строке. Для CSV-пути (всё строки) — старая логика regex сохраняется. Гибридный подход: проверяем тип значения, если строка — применяем regex-эвристику.

## Route контракт (обратная совместимость)

Решение для разницы «один источник (CSV) vs массив (xlsx)»: **route всегда возвращает массив** `{"sources": [...], "count": N}`. Это чище, чем полиморфный ответ. Фронтенд адаптивно обрабатывает список. Для CSV массив всегда длины 1.

## Что НЕ делаем
- ❌ Старый `.xls` (нужен `xlrd` — лишняя зависимость, legacy-формат)
- ❌ UI выбора листа (каждый лист → отдельный источник, пользователь выбирает через существующий селектор)
- ❌ Формулы (берём `data_only=True` — значения, а не `=SUM(...)`)
- ❌ Стили/форматирование Excel (только данные)

## Критерии готовности
1. Загрузка `.xlsx` с 2 листами создаёт **2 источника** в селекторе с именами «Файл · Лист1», «Файл · Лист2».
2. Типы распознаются точнее, чем из CSV: числовые колонки → INTEGER, даты → TEXT (ISO), без regex-угадывания.
3. Существующая CSV-загрузка работает без изменений (обратная совместимость).
4. Пустой файл или пустые листы → понятная ошибка.
5. Тесты покрывают: многолистовый xlsx, типы, пустые листы, coвместимость CSV.
6. 61+ существующий тест остаётся зелёным.
