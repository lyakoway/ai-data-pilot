# Polish Ксюши/RAG (Этап 7) — план

## Контекст

Главная задача: показать, что Ксюша **действительно использует документы**, а не просто отвечает LLM-ом. Сейчас sources — короткие сниппеты (220 chars) без раскрытия, без цитирования в тексте ответа, без trace.

**Решения пользователя:** UI-first (фрагменты + trace), без изменения retrieval-алгоритма.

**Переиспользование из ai-RAG-chat:** паттерн inline-цитат `[1]` (`citations.tsx`) и source-cards с relevance (`SourceList.tsx`). Без векторной инфраструктуры (ChromaDB/fastembed) — для 3 markdown-доков keyword-overlap достаточен.

## Что делаем

### 1. Inline-цитаты `[1]` в ответе Ксюши
Ксюша получает инструкцию в системном промпте: **цитировать источники в формате `[1]`, `[2]`** прямо в тексте ответа. Номера соответствуют индексам в массиве `sources`. Фронтенд парсит `[n]` в тексте и превращает в кликабельные бейджи (как в ai-RAG-chat `citations.tsx`). Клик → скролл к нужному source + flash.

**Backend:** обновляю `SYSTEM` промпт Ксюши — добавляю правило «ссылайся на источники [1], [2]...». Mock-ответ тоже получает цитаты.
**Frontend:** `injectCitations()` walker по React-дереву (из ai-RAG-chat), markdown-component wiring в ResultCard.

### 2. Source cards с раскрытием фрагментов + score
Сейчас: `{id, title, snippet(220 chars)}`. Будет: `{id, title, snippet, full_text, score}`.

- **Backend:** `DocChunk` уже имеет полный `text` — отдаю его целиком в source (не обрезаю до 220). Добавляю `score` из retrieval (нормализованный 0..1).
- **Frontend:** каждая source-карточка раскрывается по клику (▸ → ▾) — показывает полный текст чанка. Показывает relevance как `%` (как в ai-RAG-chat SourceList). Хайлайт слов запроса в раскрытом тексте (`<mark>`).

### 3. Trace для Ксюши (retrieval → answer steps)
Ксюша получает steps как у Олега, эмитится через тот же SSE `/api/chat/stream`:
- `retrieval` — «Ищу по документам» → `{fragments: N, top_score}`
- `answer` — «Формирую ответ»

**Backend:** `run_ksyusha_streaming(on_step)` — аналогично `run_oleg_streaming`. Старый `run_ksyusha()` — обёртка.
**Frontend:** App.tsx использует chatStream для Ксюши тоже (сейчас только Олег). AgentTrace рендерит steps Ксюши.

### 4. Хайлайт совпадений в раскрытых фрагментах
В раскрытом тексте source подсвечиваются слова из запроса пользователя (`<mark>`). Простой tokenizer + regex-замена, берём query-токены (длина ≥3) и оборачиваем совпадения. Это строим сами (в ai-RAG-chat этого нет).

## Что НЕ делаем
- ❌ Vector retrieval / ChromaDB / fastembed (для 3 доков keyword достаточен; это отдельный большой шаг)
- ❌ Token chunking / tiktoken (markdown-доки короткие)
- ❌ Парсеры PDF/DOCX (у Ксюши только markdown)
- ❌ Гибридный BM25+dense retrieval
- ❌ Agent Loop для Ксюши (она не нуждается в multi-step tool-calling)

## Критерии готовности
1. Ответ Ксюши содержит inline-цитаты `[1]`, `[2]` — кликабельные, при клике скролл к нужному source + flash.
2. Source cards раскрываются по клику — полный текст чанка + relevance % + хайлайт слов запроса.
3. Trace: пользователь видит «Ищу по документам ✓ → Формирую ответ ✓» (SSE streaming).
4. Mock-режим тоже работает (цитаты в mock-ответе, steps).
5. Олег не затронут — все 102 теста остаются зелёными.

## Риск-митигация
- Промпт с правилом цитирования — LLM может не всегда цитировать. Запасной вариант: если `[n]` отсутствует в ответе — работаем как раньше (sources снизу, без inline).
- Keyword retrieval не меняется — существующие результаты сохраняются.
- Ксюша streaming — переиспользует существующий SSE endpoint, тот же контракт.
