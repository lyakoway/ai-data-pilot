# Параметризованные сценарии (Этап 6) — план

## Контекст

Сейчас сценарий = сохранённый текст промпта. Клик «Запустить» отправляет его Олегу как есть. Параметризация превращает промпт в **шаблон с переменными** `{period}`, `{group_by}` и т.д., а при запуске показывает форму для ввода значений. Один сценарий — бесконечное переиспользование.

## Архитектура

### Модель параметра
```python
{
  "name": "period",           # ключ для подстановки {period}
  "label": "Период (дней)",   # человекочитаемо в форме
  "type": "number",           # number | text | select
  "default": 30,              # значение по умолчанию
  "options": ["a", "b"]       # только для select
}
```

### Подстановка значений
Промпт `«Покажи выручку за последние {period} дней»` + `{"period": 90}` → `«Покажи выручку за последние 90 дней»`. Простая `str.format`-подстановка с protect от отсутствующих ключей (KeyError → оставить как есть). Сценарий без параметров работает как раньше.

### Где живёт форма
**Модальное окно** поверх центра экрана при клике на сценарий с параметрами. Если параметров нет — немедленный запуск (как сейчас). Модалка чище для узкого sidebar (300px) и мобильных.

## Подстановка значений (детали)
- Используем `str.format_map(SafeDict)` — словарь, который для отсутствующих ключей оставляет `{key}` как есть (не падает)
- Значения приводятся к строке; для `select` берётся выбранная option
- Если `values` не передан — используются `default` из описания параметра
- Пустой `parameters` (null/[]) = обычный сценарий, промпт не меняется

## Seed-сценарии с параметрами
1. **«Выручка по регионам»**: `period` (30 по умолчанию), `group_by` (регион/город/месяц)
2. **«Топ городов»**: `limit` (10), `metric` (поездки/выручка/пользователи)
3. Остальные — без параметров (как раньше)

## Критерии готовности
1. Клик на «Выручка по регионам» → модалка с двумя полями (Период=30, Группировка=регион ▾).
2. Меняем period=90, group_by=город → Олег получает «...за последние 90 дней... по городам».
3. Сценарий без параметров запускается сразу (без модалки), как раньше.
4. Сценарии, созданные через «Сохранить», пока без параметров (параметризация созданных вручную — следующий шаг, если нужно).
5. Все 92 существующих теста остаются зелёными.

## Что НЕ делаем
- ❌ UI создания/редактирования параметров (пока только seed-сценарии; ручное создание остаётся простым промптом)
- ❌ Валидация типов на backend (доверяем UI-форме; подстановка = простая строка)
- ❌ Сохранение последних введённых значений (stateless модалка)
